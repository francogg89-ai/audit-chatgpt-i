## Defecto nuevo detectado

### D-04 — DE DISEÑO — BLOQUEANTE

`D1` define:

```text
N_CONSTRUCTOR = git -C <work>  rev-list --count --first-parent <corte-work>
N_AUDITOR     = git -C <audit> rev-list --count --first-parent <corte-audit>
```

y afirma que esa cuenta es exactamente equivalente a:

- toda entrega autoritativa del CONSTRUCTOR = un commit de `work-*`;
- toda intervención autoritativa del AUDITOR = un commit de `audit-*`.

REVOLUTIONS P1/P2 establece precisamente que una intervención principal es un commit autoritativo y que todo commit de `work-*` es una entrega. No establece una convención de commits ni un invariante que convierta exclusivamente la cadena de primer padre en el conjunto completo de hechos que cuentan.

`--first-parent` no cuenta commits alcanzables por una rama de segundo padre de un merge. Por lo tanto, ante una historia Git válida que contenga un merge, la fórmula puede producir un número menor que la cantidad de commits que el propio plan y REVOLUTIONS dicen que cuentan. En ese caso una cadencia `10, 20, 30...` dejaría de corresponder a las intervenciones autoritativas reales.

Propiedad que debe quedar resuelta: la derivación periódica debe contar exactamente los hechos Git que la definición normativa declara contables, o establecer una condición válida y compatible con REVOLUTIONS que haga equivalentes ambos conjuntos. No puede depender de una propiedad de la historia que el plan no garantiza.

El AUDITOR no prescribe qué comando o estructura Git debe elegir el CONSTRUCTOR.
